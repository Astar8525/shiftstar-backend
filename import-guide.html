Import Guide

Everything you need to know about importing your production data into ShiftStar — step by step.

1. What is the Import tab?

The Import tab lets you bring your real production data into ShiftStar so it can calculate your actual OEE — not estimates. You paste your data directly from SAP, MRP, or any spreadsheet and ShiftStar does the rest.

Once imported ShiftStar calculates:

  • OEE — Availability × Performance × Quality from your actual numbers
  • Throughput — total good units produced
  • Defect rate — percentage of units rejected or scrapped
  • Downtime impact — how much downtime affected your availability

The data is saved to your company's database so your trend analysis, shift history, and AI analysis all reflect your real production performance.

Tip: You don't need to import data to use ShiftStar. You can start by logging downtime events manually and import production data when you're ready.

2. How to import — step by step

1
Export your data from your system
In SAP, MRP, or Excel — run your production report and export it as a CSV file. If you're in Excel, go to File → Save As → CSV (Comma delimited). If you're in SAP, use the spreadsheet export button in your report view.
2
Open the CSV file in Notepad or any text editor
Right-click your CSV file and choose "Open with → Notepad." You'll see your data as rows of text separated by commas. This is what you'll paste into ShiftStar.
3
Select all and copy
In Notepad press Ctrl+A to select everything, then Ctrl+C to copy. Make sure the first row contains your column headers — ShiftStar needs these to identify your data.
4
Go to the Import tab in ShiftStar
Click the Import tab at the top of your dashboard. You'll see a large text area with placeholder text showing an example format.
5
Paste your data
Click inside the text area and press Ctrl+V to paste. You should see your data appear with the header row at the top and data rows below.
6
Click "Import & calculate OEE"
ShiftStar will auto-detect your column names, calculate OEE, and save the results to your company database. You'll see a success message and be taken to the Dashboard where your metrics are now showing real numbers.
Not sure what your data looks like? Download one of our sample files below and paste it in to see how the import works before using your own data.

3. Importing from SAP

ShiftStar accepts CSV exports from SAP PP (Production Planning) and SAP MM (Materials Management). Here's how to export from the most common SAP reports:

From SAP PP — Production Order Confirmation (CO15 / COOIS)

1
Run your production report
In SAP go to transaction COOIS or CO15. Set your date range and plant, then execute the report.
2
Export to spreadsheet
Click the spreadsheet icon in the toolbar (or go to List → Export → Spreadsheet). Choose "CSV" or "Comma Separated" format.
3
Open and paste into ShiftStar
Open the downloaded file in Notepad, copy all, and paste into the ShiftStar Import tab.

ShiftStar will automatically recognize SAP column names like Confirmed.Qty, Scrap.Qty, Planned.Time.min, and Downtime.min.

4. Importing from MRP systems

ShiftStar works with any MRP system that can export to CSV or Excel. The column names just need to map to what ShiftStar understands — and ShiftStar recognizes many common variations automatically.

Common MRP export column names ShiftStar recognizes:

  • good_units or units_good or confirmed_qty → units produced
  • rejected_units or defects or scrap_qty → units defective
  • planned_hrs × 60 or planned_time_min → planned time
  • downtime_min or dt_min → downtime
production_date,shift,resource_id,good_units,rejected_units,planned_hrs,downtime_min 2026-09-01,Day,Resource-A,482,9,8,18 2026-09-01,Afternoon,Resource-B,451,12,8,35 2026-09-01,Night,Resource-C,398,15,8,52
Note: If your MRP uses hours instead of minutes for planned time, ShiftStar will try to auto-detect this. If OEE looks unusually low, your planned time may be in hours — multiply by 60 in your spreadsheet before importing.

5. Importing from Excel or a generic CSV

If you track production data in Excel, ShiftStar can import it directly as long as you save it as CSV first.

How to convert Excel to CSV

1
Open your Excel file
Make sure your data has a header row at the top with column names.
2
File → Save As → CSV
Choose "CSV (Comma delimited) (*.csv)" from the file type dropdown. Save to your desktop.
3
Open in Notepad, copy, paste into ShiftStar
Right-click the CSV file → Open with → Notepad. Select all (Ctrl+A), copy (Ctrl+C), then paste into ShiftStar's Import tab.

The simplest format ShiftStar accepts — if you want to build your own template:

machine,units_produced,units_defect,planned_time_min,downtime_min,ideal_cycle_sec Line 1,450,9,480,22,22 Line 2,510,13,480,15,28 Line 3,382,7,480,38,35

8. Troubleshooting

I get "Need at least: units_produced and planned_time_min columns" +
ShiftStar couldn't find your units produced or planned time columns. Check that your header row uses one of the supported column names listed in Section 6. The most common fix is renaming your column to units_produced and planned_time_min.
My OEE looks much lower than expected +
This usually means your planned time is in hours instead of minutes. ShiftStar expects minutes. If your planned time column shows 8 (hours) instead of 480 (minutes), open your CSV in Excel, multiply the planned time column by 60, save as CSV, and re-import. Also check that your ideal cycle time (if provided) is in seconds per unit — not minutes.
My data pasted but ShiftStar shows the wrong numbers +
Make sure you're pasting only the data — no extra rows above the header, no totals row at the bottom, and no merged cells (which don't export cleanly from Excel). Also check that your delimiter is a comma, not a semicolon. Some European Excel versions default to semicolons — you can fix this in Excel's CSV export settings or by doing Find & Replace (semicolons → commas) in Notepad.
I see "Could not save to database: Failed to fetch" +
This usually means you're not logged in or your session expired. Refresh the page, sign in again, and try the import again. If the error persists, try a different browser or clear your browser cache.
My SAP export has extra columns ShiftStar doesn't recognize +
That's fine — ShiftStar ignores columns it doesn't recognize and only uses the ones it knows. You don't need to delete extra columns before importing. As long as the columns ShiftStar needs are present, the import will work correctly.
